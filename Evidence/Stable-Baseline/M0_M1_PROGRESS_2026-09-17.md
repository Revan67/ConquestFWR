## Narrow preview repair

UnbornMeshList now borrows GetEngineArchtype from an existing meshArch, falling
back to the legacy field only if no wrapper exists. It does not assign the
platform's archIndex: doing that also changes ObjectTransform::initTransform's
normal creation branch and the destructor's reference behavior. Those broader
ownership changes require separate validation.

Both ship/platform previews reject invalid instance creation before constructing
or caching MeshInfo, and reject mismatched shared renderer/tree sizes. Missing
archetype/data/handle failures return safely. Entry fields are initialized;
cleanup explicitly makes MeshInfo non-owning and releases the Engine tree once.
RenderMeshAt handles failed creation without dereferencing a null entry.

MeshRender::Render rejects invalid instances and performs valid non-mesh Engine
fallback before fetching/dereferencing mesh material data. A null geometry result
cannot reach the new material-cache refresh. This is defense in depth, not the
sole HQ fix.

Platform shadow-preview creation and platform blinkers were two additional
legacy-index consumers. They now borrow the same wrapper-owned Engine archetype
handle. Shadow construction validates both the archetype and returned instance,
and leaves `shadowPlayer` unset on failure so a later frame can retry. Normal
platform creation and wrapper ownership remain unchanged.
